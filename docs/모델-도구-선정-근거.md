# 모델·도구 선정 근거 (후보 비교 결과)

> 본 문서는 "일일보고 취합 · 주간보고 자동화 도구"에서 사용할 로컬 LLM과 도구를
> 선정한 근거를 정리한다. 후보 모델 비교 결과와 채택 판단을 담는다.
> 상세 정확도 자체 평가(항목별 추출 정확도 표)는
> [정확도-자체-평가.md](./정확도-평가.md)를 참고한다.

---

- **채택: qwen3.5-4b** (추론 끄기) — 완료 업무·진행 중 업무 추출이 가장 안정적이고
  gold 데이터셋에서 1위를 기록한 이력이 있으며, JSON·스키마 준수율 100%
- **1순위로 고른 기준**: micro F1(전체 추출 종합 점수) + 항목별 균형
  - 2026-08-06 재측정: gold nuextract3 82.6% > qwen 81.2% > gemma 76.5%
  - 2026-08-06 재측정: report nuextract3 77.6% > gemma 76.4% > qwen 73.3%
- **nuextract3**: 종합 점수는 1위지만 gold에서 qwen과 1.4%p 차로 근소하고,
  이슈(65.2%)·협조 요청(69.6%) 추출이 qwen 대비 낮음
- **gemma**: 재현율(84.1%)은 높으나 정밀도(70.2%)가 크게 낮아 오탐이 많음
- **micro F1 이란?** — 모델이 뽑아낸 업무 항목(완료·진행·이슈·요청·계획)이 정답과
  얼마나 겹치는지를 0~100%로 나타낸 종합 점수. 100%면 완벽히 뽑았다는 뜻. (자세한 설명은
  [정확도-자체-평가.md](./정확도-평가.md) '한눈에 보기' 참고)

## 1. 요구사항

- **입력**: 자유 형식 일일보고 원문 (개조식, 줄글, 메신저체, 표, 한 줄, 영문 혼합 등)
- **출력**: `backend/model_asset/json_Schema.json` 스키마를 준수하는 JSON
  - 프로젝트명 + 완료 업무 / 진행 중 업무 / 이슈(+상태) / 협조 요청 / 다음 계획
- **환경**: 외부 API 호출 불가
- **제약**:
  - Q4 양자화 GGUF 모델만 로드 가능
  - 추론(reasoning)은 기본적으로 끔 (`reasoning_effort: "none"`)
  - 응답 지연은 보고 1건당 20초 이내를 목표

## 5. 채택 판단

### 5.1 최종 채택: **qwen3.5-4b** (추론 끄기)

2026-08-06 재측정에서 nuextract3가 종합 점수(82.6%/77.6%)는 1위를 기록했지만,
다음 근거로 **qwen3.5-4b를 기본 모델로 유지**한다.

- **완료 업무(91.8%)·진행 중 업무(79.3% gold)의 안정성**: 완료 업무는 세 모델 중 최고,
  gold 기준 오탐이 0건(정밀도 100%)
- **이슈 추출 정밀도가 가장 높음**: qwen 81.2% (nuextract 62.5%, gemma 56.7%) —
  잘못된 이슈를 만들어내는 오탐이 적어, 이슈를 실제보다 부풀리지 않음
- **협조 요청 추출**: gold 75.0%로 세 모델 중 최고
- **JSON·스키마 준수율 100%**, 빈 보고 처리 100%
- **속도**: 평균 지연 2.65~3.04초로 20초 목표 대비 충분히 빠름 (gold에서 32건 처리 3분 내외)

**한계 (투명하게 공개)**:
- report 데이터셋(자체 작성)에서 종합 3위(73.3%)로, nuextract3(77.6%)와 4.3%p 차이
- 다음 계획 추출(68.2%)이 상대적으로 약함

> nuextract3로 기본 모델을 바꾸는 것도 유효한 선택지다. 종합 점수 1위이고 지연도
> 가장 짧다(2.09~2.54초). 다만 이슈 오탐(FP 9건 gold)이 많아 이슈 신뢰도가 낮아질 수
> 있고, 완료 업무 정밀도(97.7%)는 높지만 qwen 대비 진행 중 업무·다음 계획의 균형이
> 떨어진다. 실제 운영에서 이슈 오탐이 문제가 되면 nuextract3로 전환을 재검토한다.

| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 5.3 운영 조건

- **로드**: `lms load qwen3.5-4b --context-length 32768 --parallel 1` (추론 모드에서 컨텍스트 부족 방지)
- **추론 차단**: 백엔드는 요청마다 `reasoning_effort: "none"`을 명시적으로 전송.
  필드를 생략하면 qwen3.5-4b가 기본적으로 추론을 켜므로(실측: 추론 1337B·16.6초)
  **생략 금지**
- **온프레미스**: LM Studio 로컬 API(`http://127.0.0.1:1234/v1`) 사용, 외부 API 미호출

## 6. 도구 선정

| 도구              | 용도          | 선정 근거                                                                                         |
| ----------------- | ------------- | ------------------------------------------------------------------------------------------------- |
| **LM Studio**     | LLM 로컬 서버 | OpenAI 호환 API 제공, GGUF Q4 로드 용이                                                           |
| **FastAPI**       | 백엔드        | OpenAI SDK 호환(`client.chat.completions.create`) |
| **SQLite**        | 저장          | 보고서 원문·구조화 결과·프로젝트 별칭 저장. 소규모 툴에 충분, 별도 DB 서버 불필요                 |
| **Vue 3 + Vite**  | 프론트엔드    | 화면 빠른 개발, docxtemplater로 워드 다운로드 지원                                                |
| **docxtemplater** | 워드 생성     | 주간보고 초안을 .docx로 내보내기                                                                  |

## 7. 실행 방법 (재현)

```bash
# gold 데이터셋 (기존)
python benchmark/run_benchmark.py qwen3.5-4b google/gemma-4-e2b nuextract3 ^
  --force --reasoning none --max-tokens 6144 --dataset gold --known-projects dataset ^
  --out-dir benchmark/results/three_models_2026-08-05_daily
python benchmark/score_benchmark.py --raw-dir benchmark/results/three_models_2026-08-05_daily --prefix three_models_2026_08_05_

# 자체 작성 테스트 보고 데이터셋
python benchmark/run_benchmark.py qwen3.5-4b google/gemma-4-e2b nuextract3 ^
  --force --reasoning none --max-tokens 6144 --dataset report --known-projects report ^
  --out-dir benchmark/results/report_2026-08-05
python benchmark/score_benchmark.py --raw-dir benchmark/results/report_2026-08-05 --prefix report_2026_08_05_ --dataset report
```
