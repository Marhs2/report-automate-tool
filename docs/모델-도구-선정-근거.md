# 모델·도구 선정 근거 (후보 비교 결과)

> 본 문서는 "일일보고 취합 · 주간보고 자동화 도구"에서 사용할 로컬 LLM과 도구를
> 선정한 근거를 정리한다. 후보 모델 비교 결과와 채택 판단을 담는다.
> 상세 정확도 자체 평가(항목별 추출 정확도 표)는

## 한눈에 보기 (요약)

**무엇을 고르는 문서인가요?**

일일보고를 자동으로 정리해 줄 AI 모델을, 정확도와 속도를 재서 한 가지로 고르는
문서입니다. 후보 7개를 벤치마크(테스트 보고 32건)로 비교했습니다.

**결론 (2026-08-05)**

- **채택: qwen3.5-4b** (추론 끄기) — 정확도 1위, 속도도 준수
- **1순위로 고른 기준**: micro F1(전체 추출 종합 점수) — qwen 83.0% > nuextract3 82.6% > gemma 77.3% (gold 데이터셋)
- **nuextract3를 버린 이유**: 종합 점수가 0.4%p 차로 비슷하지만 느림(+3초)
- **gemma를 버린 이유**: 가장 빠르지만 정확도가 5%p 이상 낮음
- **micro F1 이란?** — 모델이 뽑아낸 업무 항목(완료·진행·이슈·요청·계획)이 정답과
  얼마나 겹치는지를 0~100%로 나타낸 종합 점수. 100%면 완벽히 뽑았다는 뜻. (자세한 설명은
  [정확도-자체-평가.md](./정확도-평가.md) '한눈에 보기' 참고)

## 1. 요구사항

- **입력**: 자유 형식 일일보고 원문 (개조식, 줄글, 메신저체, 표, 한 줄, 영문 혼합 등)
- **출력**: `backend/model_asset/json_Schema.json` 스키마를 준수하는 JSON
  - 프로젝트명 + 완료 업무 / 진행 중 업무 / 이슈(+상태) / 협조 요청 / 다음 계획
- **환경**: 외부 API 호출 불가
- **제약**:
  - Q4 양자화 GGUF 모델만 로드 가능
  - 추론(reasoning)은 기본적으로 끔 (`reasoning_effort: "none"`)
  - 응답 지연은 보고 1건당 20초 이내를 목표

## 5. 채택 판단

### 5.1 최종 채택: **qwen3.5-4b** (추론 끄기)

- gold 데이터셋에서 micro F1 **83.0%** 로 세 모델 중 1위
- 완료 업무(90.7%)·진행 중 업무(84.6%)·다음 계획(83.7%)이 모두 높고 균형적
- JSON·스키마 준수율 100%
- 평균 지연 18.99초로 nuextract3(22.10초)보다 짧아, 보고 1건당 처리 시간이 짧음
- 컨텍스트 최대 262K로 긴 회의록·오래된 보고서 보존 케이스에도 여유

### 5.2 제외 사유

| 모델 | 제외 사유 |
| --- | --- |
| **nuextract3** | 프로젝트 F1·이슈·협조 요청은 가장 높으나 micro F1이 qwen과 0.4%p 차이로 근소하고, 평균 지연이 3초가량 길다. 추출 특화 모델이지만 일반 지시 수행이 상대적으로 약해 요청/다음 계획 판단에서 일관성이 떨어짐. |
| **google/gemma-4-e2b** | 평균 지연은 가장 짧으나(16.09초) micro F1 77.3%로 세 모델 중 최하. 진행 중 업무(73.7%)·다음 계획(69.8%) 추출 성능이 낮아, 정확도가 우선인 용도에 부적합. |
| nvidia/nemotron-3-nano-4b | micro F1 66.7%로 상위 3개 대비 부족 |
| kanana-2-3b-instruct-i1 | micro F1 44.8%, 이슈 추출 17.0%로 부족 |
| lfm2.5-8b-a1b | JSON 완성도 90.6%, micro F1 20.7%로 부적합 |
| minicpm5-1b | micro F1 15.8%, 이슈·협조 요청 추출 불가 |

### 5.3 운영 조건

- **로드**: `lms load qwen3.5-4b --context-length 32768 --parallel 1` (추론 모드에서 컨텍스트 부족 방지)
- **추론 차단**: 백엔드는 요청마다 `reasoning_effort: "none"`을 명시적으로 전송.
  필드를 생략하면 qwen3.5-4b가 기본적으로 추론을 켜므로(실측: 추론 1337B·16.6초)
  **생략 금지**
- **온프레미스**: LM Studio 로컬 API(`http://127.0.0.1:1234/v1`) 사용, 외부 API 미호출

## 6. 도구 선정

| 도구 | 용도 | 선정 근거 |
| --- | --- | --- |
| **LM Studio** | LLM 로컬 서버 | OpenAI 호환 API 제공, GGUF Q4 로드 용이, GPU 오프로드·병렬 슬롯 제어(`lms load --parallel`) 지원. 온프레미스 요구 충족 |
| **FastAPI** | 백엔드 | OpenAI SDK 호환(`client.chat.completions.create`), 비동기 처리, 스키마 검증(jsonschema) 내장 용이 |
| **SQLite** | 저장 | 보고서 원문·구조화 결과·프로젝트 별칭 저장. 소규모 툴에 충분, 별도 DB 서버 불필요 |
| **Vue 3 + Vite** | 프론트엔드 | 화면 빠른 개발, docxtemplater로 워드 다운로드 지원 |
| **docxtemplater** | 워드 생성 | 주간보고 초안을 .docx로 내보내기 |

## 7. 실행 방법 (재현)

```bash
# gold 데이터셋 (기존)
python benchmark/run_benchmark.py qwen3.5-4b google/gemma-4-e2b nuextract3 ^
  --force --reasoning none --max-tokens 6144 --dataset gold --known-projects dataset ^
  --out-dir benchmark/results/three_models_2026-08-05_daily
python benchmark/score_benchmark.py --raw-dir benchmark/results/three_models_2026-08-05_daily

# 자체 작성 테스트 보고 데이터셋
python benchmark/run_benchmark.py qwen3.5-4b google/gemma-4-e2b nuextract3 ^
  --force --reasoning none --max-tokens 6144 --dataset report --known-projects report ^
  --out-dir benchmark/results/report_2026-08-05
python benchmark/score_benchmark.py --raw-dir benchmark/results/report_2026-08-05 --prefix report_2026_08_05_
```
