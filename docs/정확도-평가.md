# 정확도 자체 평가 (테스트 보고 32건 기준 항목별 추출 정확도 표)

> 채택 모델 **qwen3.5-4b**(추론 끄기)가 자유 형식 일일보고를 구조화할 때
> 후보 비교·선정 근거는 [모델-도구-선정-근거.md](./모델-도구-선정-근거.md) 참고.

---


- 세 모델 모두 JSON을 100% 올바른 형식으로 출력했습니다.
- **종합 정확도(micro F1, gold 데이터셋)**: nuextract3 **82.6%** / qwen3.5-4b 81.2% / gemma 76.5%
- **종합 정확도(micro F1, 자체 작성 테스트 보고 32건)**: nuextract3 **77.6%** / gemma 76.4% / qwen3.5-4b 73.3%
- 두 데이터셋 모두 nuextract3가 종합 1위지만, qwen3.5-4b는 **완료 업무(91.8% gold)·이슈 정밀도(81.2%)** 가
  세 모델 중 가장 높고 오탐이 적습니다.
- 세 모델 차이는 3.5~6%p 안팎입니다. 모델보다 **작성 스타일(줄글·메신저·표)** 이 정확도에 더 큰 영향을 줍니다.

## 1. 평가 대상·방법

### 1.1 평가 데이터 (자체 작성 테스트 보고 32건)

`test-data/daily-reports.md` — 2주치(2026-07-13 ~ 07-24), 인물 4명, 프로젝트 3개.

| 구분        | 값                                                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 인물        | 정동일, 신찬혁, 김재휘, 박현빈                                                                                                           |
| 프로젝트    | 일일보고취합, 명함주소록, 회의록자동화                                                                                                   |
| 기간        | 2026-07-13 ~ 2026-07-24 (2주, 10영업일)                                                                                                  |
| 건수        | 32건                                                                                                                                     |
| 스타일      | 개조식 9, 줄글 11, 메신저체 4, 표 2, 한 줄 2, 줄글+영문 혼합 2, 혼합 1, 업무 없음 1                                                      |
| 엣지 케이스 | 긴 글 줄바꿈, 중복 명함 판단, 표 구분선 누락으로 행 병합(D06), '개발 개발' 오타(D04), 같은 업무 상태 모순(D06), 사내 교육만 참석(D16) 등 |

정답(gold)은 `backend/model_asset/prompt.txt` + `json_Schema.json` 규칙에 따라
사람이 직접 라벨링해 `benchmark/dataset/gold_dataset_report.json`으로 만들었다.
원문의 프로젝트명·기능·화면명·이슈 문구는 전부 이 데이터셋에서 비롯한다.

### 1.2 채점 방식

`benchmark/score_benchmark.py` — 표기 정규화 + 별칭 병합 후 프로젝트 매칭,
프로젝트 안에서 필드별 문자 bigram Dice 유사도 0.5 이상을 정답으로 보는
탐욕 매칭. 지표는 정밀도(precision)·재현율(recall)·F1.

**점수 3종 세트 (쉽게)**

| 점수              | 우리말        | 뜻                          | 비유                                 |
| ----------------- | ------------- | --------------------------- | ------------------------------------ |
| 정밀도(Precision) | 정확히 뽑음   | 뽑아낸 것 중 진짜 맞는 비율 | 그물에 걸린 것 중 원하는 물고기 비율 |
| 재현율(Recall)    | 빠짐없이 뽑음 | 정답 중 잡아낸 비율         | 실제 물고기 중 그물에 걸린 비율      |
| F1                | 종합 점수     | 정밀도·재현율의 조화평균    | 둘 다 잘하는지 종합한 점수           |

- **micro F1**: 항목(완료/진행/이슈/요청/다음 계획) 전체 합산 기준 F1. 항목 수가 많은 필드가 점수에 더 영향
- **항목별 F1**: 필드별 TP/FP/FN 합산 F1. 각 필드가 얼마나 정확한지
- **이슈 상태 정확도**: 매칭된 이슈 중 status(해결/미해결)가 일치한 비율
- **빈 보고 처리**: 업무 없음 보고에서 `projects: []`를 정확히 출력한 비율

### 1.3 실행 조건

- 프롬프트: `backend/model_asset/prompt.txt`
- 스키마: `backend/model_asset/json_Schema.json`
- 추론: `reasoning_effort: "none"`
- max_tokens: 6144, temperature: 0.1
- 재측정일: 2026-08-06 (LM Studio 로컬, `--force` 재실행)

## 5. 채택 모델 한계와 운영 시 보완

- **다음 계획 추출**(68.2% report)이 상대적으로 약함 → 사용자가 초안 편집 화면에서 보완
- **진행 중 업무 오탐**(FP 18건 report)이 많음 → 80% 진행 등 미완료 표현이 진행 중으로 잡히는 경향
- **줄글·영문 혼합 보고**는 정확도가 크게 낮음 → 보고 작성 가이드(개조식 권장)로 보완
