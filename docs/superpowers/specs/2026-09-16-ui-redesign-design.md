# UI 대규모 개선 설계

작성일: 2026-09-16
대상: `frontend/` (Vue 3 + Vite SPA)

## 목표

현재 톤(베이지 `#f7f2eb` + 올리브 `#8b9a6e`)을 유지하면서, 디자인 토큰이 없어 생긴 시각적 불일치를 없애고 앱 셸(사이드바·탑바·페이지 헤더·반응형)을 재구성한다. 사용자가 결과가 마음에 들지 않을 경우 한 번의 명령으로 완전히 되돌릴 수 있어야 한다.

### 성공 기준

- 10개 화면 전체가 동일한 간격·타이포·색 스케일을 사용한다.
- 사이드바 접기, 본문 폭 제한, 탑바 경로 표시, 페이지 헤더 통일, 오버레이 드로어 반응형이 동작한다.
- `npm run build`가 성공하고, 10개 화면에서 콘솔 에러가 없다.
- `git switch main` 한 번으로 개선 이전 상태로 완전히 복귀할 수 있다.

### 범위에서 제외

- 백엔드(`backend/`) 변경
- 다크 모드 등 추가 테마
- Tailwind 등 CSS 프레임워크 도입
- 기능 추가 및 화면 로직 변경 (스타일·레이아웃·헤더 마크업만 다룬다)

## 현재 상태

- 전역 스타일: `frontend/src/style.css` 1,247줄. 셸·공통 컴포넌트·문서형 화면 스타일이 한 파일에 섞여 있다.
- 컴포넌트 scoped CSS 약 1,800줄. 가장 큰 파일은 `project-name.vue`(366줄), `user-activities.vue`(363줄), `projects-list.vue`(332줄).
- `--bg`와 `--bg-elevated`가 같은 값이라 카드가 배경과 구분되지 않는다.
- `--shadow`, `--shadow-raised`가 모두 `none`이다.
- `font-weight`가 500·600·650·700으로 흩어져 있다.
- 간격이 6·8·10·12·14·16·20px로 컴포넌트마다 임의로 쓰인다.
- `App.vue`의 `pageMeta`가 경로 정규식 분기로 화면 제목·액션을 결정한다. 라우트에는 `meta`가 없다.
- `.page-header`가 `:has()` 셀렉터로 자기 자신을 숨겨, 화면마다 제목이 보이거나 보이지 않는다.
- 860px 이하에서 사이드바가 가로 스크롤 탭 줄로 바뀌고 "내일 할 일" 카드는 숨겨진다.

## 접근 방식

토큰 레이어를 먼저 만들고 그 위에서 스타일을 재작성한다(위험 낮음). 셸과 페이지 헤더는 구조까지 변경한다(요청된 레이아웃 개편이 이 두 곳에 집중되어 있다). 개별 화면의 템플릿은 헤더 부분만 교체하고 나머지 마크업은 유지한다.

## 설계

### 1. 디자인 토큰 (`frontend/src/styles/tokens.css`)

- **색**
  - 배경 3단계: `--bg`(페이지), `--surface`(카드, 따뜻한 밝은 흰색), `--surface-soft`(중첩 영역)
  - 텍스트 3단계: 강조·본문·보조
  - 테두리 2단계: 기본·강조
  - 액센트: 기존 올리브 기준의 기본·호버·소프트 배경·테두리 변형
  - 상태 색(성공·경고·위험·정보): 각각 전경·배경·테두리 3쌍
- **간격**: `--space-1`~`--space-8` = 4·8·12·16·20·24·32·48px. 기존 임의 값은 가장 가까운 단계로 흡수한다.
- **타이포**: 크기 11·12·13·14·16·20·24·30px, 줄높이 토큰, 굵기는 500·600·700만 사용한다. `word-break: keep-all`은 유지한다.
- **반경**: 8·12·16·pill. 버튼은 pill 유지, 입력 필드는 pill에서 12px로 변경한다.
- **모션**: 전환 시간 2단계와 이징 토큰. `prefers-reduced-motion` 처리는 유지한다.
- **그림자는 도입하지 않는다.** 표면 구분은 `--bg`/`--surface` 밝기 차이와 테두리 2단계로만 처리한다. 기존 `--shadow*` 토큰은 제거한다.

### 2. CSS 파일 구조

`frontend/src/styles/` 아래로 분리하고 `style.css`는 진입점(import만)으로 남긴다.

| 파일 | 내용 |
| --- | --- |
| `tokens.css` | 토큰 정의 |
| `base.css` | 리셋, 타이포 기본, 스크롤바, 포커스 링, reduced-motion |
| `shell.css` | 사이드바, 탑바, 드로어, 페이지 컨테이너 |
| `components.css` | 버튼, 입력, 카드, 칩, 상태 배너, 토스트, 모달, 빈 상태 |
| `report-doc.css` | 문서형 화면(일일보고 상세·주간 상세·분석 결과) 공용 스타일 |

### 3. 앱 셸 (`App.vue`, `shell.css`)

- **사이드바 접기**: 272px ↔ 64px 두 상태. 상단의 현재 빈 영역을 앱 이름 + 토글 버튼으로 채운다. 접힌 상태에서는 내비게이션이 아이콘만 남고 라벨은 `title` 툴팁으로 제공하며, "내일 할 일" 카드와 사용자 이름·팀 텍스트는 숨긴다. 상태는 `localStorage`에 저장한다.
- **탑바**: 라우트 메타를 읽어 "상위 화면 › 현재 화면" 형태의 경로를 표시하고, 우측에 주요 액션 자리를 고정한다. 좁은 화면에서는 좌측에 드로어 토글(햄버거)을 둔다.
- **반응형**: 860px 이하에서 사이드바를 오버레이 드로어로 전환한다. 드로어 안에서는 전체 내비게이션과 "내일 할 일"을 모두 볼 수 있다. 오버레이 클릭과 `Escape`로 닫히고, 라우트 이동 시 자동으로 닫힌다.

### 4. 라우터 메타 (`router/index.js`)

각 라우트에 `meta`를 추가한다.

- `title`: 화면 제목
- `parent`: 상위 화면의 라우트 이름 (없으면 생략)
- `action`: 주요 액션 `{ to, label }` (없으면 생략)
- `navKey`: 사이드바 활성 항목 판정 키

`App.vue`의 `pageMeta` 정규식 분기와 `isNavActive`의 경로 하드코딩을 이 메타 기반으로 대체한다. 리다이렉트 전용 라우트(`/weekly-report`, `/report/:id`)는 변경하지 않는다.

### 5. 페이지 헤더 (`components/ui/AppPageHeader.vue`)

제목·설명·필터·액션 네 자리를 가진 컴포넌트를 만들고, 10개 화면이 이를 사용한다. 필터와 액션은 슬롯으로 받는다. `.page-header`의 `:has()` 기반 자기 숨김 규칙은 제거한다.

본문 폭: 목록·폼 화면은 최대 1120px, 2열 문서형 화면은 1280px을 유지한다. 페이지 좌우 여백은 토큰 한 값만 사용한다.

### 6. 화면별 적용

10개 화면의 scoped CSS에서 하드코딩된 색·간격·굵기를 토큰으로 치환한다. 여러 화면에 중복된 패턴(필터 바, 목록 테이블, 상태 칩, 프로젝트 배지)은 `components.css`로 승격해 중복을 제거한다. 각 화면의 조건부 렌더링·상태 로직은 건드리지 않는다.

대상: `projects-list.vue`, `report.vue`, `report-result.vue`, `weekly-report.vue`, `weekly-detail.vue`, `user-activities.vue`, `project-timeline.vue`, `project-name.vue`, `team-select.vue`, `user-select.vue`

## 되돌리기 안전망

1. 커밋되지 않은 현재 변경을 `main`에 저장 커밋으로 고정한다.
2. `ui-redesign` 브랜치를 만들고 모든 작업을 그 브랜치에서만 수행한다.
3. 브랜치 안에서도 단계별로 커밋을 나눈다: 토큰 → CSS 분리 → 셸 → 라우터 메타·페이지 헤더 → 화면별 스타일.

전체 되돌리기는 `git switch main`, 부분 되돌리기는 해당 단계 커밋의 `git revert`로 처리한다.

## 검증

- `npm run build` 성공
- `npm run dev` 실행 후 브라우저로 10개 화면 방문: 콘솔 에러 없음, 스크린샷 확인
- 사이드바 접기·펼치기와 새로고침 후 상태 유지 확인
- 좁은 화면(≤860px)에서 드로어 열기·닫기 확인
- 데이터가 없는 화면이 빈 상태로 정상 렌더링되는지 확인
