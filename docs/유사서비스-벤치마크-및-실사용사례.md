# 유사 서비스 벤치마크 및 실사용 사례 조사

> 일일보고 취합 · 주간보고 자동화 도구(`report-automate-tool`)의 경쟁 제품, 직장인 커뮤니티 실사용 후기, 일일보고 템플릿 조사.
> 조사일: 2026-09-18. 공개 마케팅/도움말/커뮤니티 원글 기준. 로그인 벽이 있는 제품은 인증된 앱 화면이 아니라 공개 문서·데모 기준.

---

## 1. 조사 목적

- 우리 앱과 비슷한 웹/앱을 찾아, **통째로 베낄 제품이 있는지**와 **화면별로 무엇을 벤치마크할지** 가른다.
- 디시인사이드, 블라인드, 클리앙, 더쿠 등에서 **실제 직장인이 일일보고를 어떻게 쓰고 욕하는지** 수집한다.
- 작성 템플릿 기능을 넣을 때 쓸 **실무 양식 목록**을 정리한다.

---

## 2. 우리 제품이 하는 일

로컬 앱(`http://localhost:5173`). 핵심 루프는 아래와 같다.

1. **보고서 작성**: 자유 텍스트 또는 PPTX를 넣고 `AI로 정리하기`
2. **구조화**: 프로젝트별 완료 / 진행 / 이슈 / 요청 / 다음 계획 JSON
3. **일일보고 목록**: 사람 × 날짜 카드, 제출 현황, 이슈 수
4. **주간 보고서**: 선택한 요일의 일일을 병합, 제출 그리드, Word/PPT 내보내기
5. **사용자 활동**: 월간 캘린더, 제출/미제출
6. **프로젝트 흐름**: 프로젝트별 일자 카드, 이슈 상태(미해결 / 해결 / 이후 언급 없음)

차별점: 슬랙 질문지가 아니라 **지저분한 원문(줄글, 개조식, 메신저, 표, PPT)을 JSON으로 추출**한다. 조사한 유명 제품 중 이 루프를 통째로 하는 곳은 없었다.

## 3. 유사 서비스 벤치마크

### 3.1 한 줄 결론

통째로 베낄 앱은 없다. **제품 북스타는 Dailybot**, 일일 필드 이름은 Geekbot + Weekdone PPP, 한국어 카피는 플로우 일일 업무 일지. 붙여넣기 추출은 우리만의 것으로 유지한다.

| 우선순위 | 제품 | 벤치마크 범위 | 비고 |
| --- | --- | --- | --- |
| 1 | [Dailybot](https://www.dailybot.com/) | 미제출, 블로커, 주간 취합, 요일 그리드 | 메인 |
| 2 | [Geekbot](https://geekbot.com/standups/) | 어제 / 오늘 / 블로커 필드 | 일일 스키마만 |
| 3 | [Weekdone PPP](https://weekdone.com/resources/plans-progress-problems) | 주간 칸, 이슈 칸 이동 | 주간·프로젝트 흐름 |
| 4 | [플로우 일일 업무 일지](https://support.flow.team/ko/flow/29313411403545) | 한국어 버튼/섹션 카피 | 입력 소스가 다름 |
| - | Range | 항목을 나중에 논의할 안건으로 꽂기 | 요청/이슈만 |
| 제외 | 잔디, 슬랙, 팀즈, Lattice, 15Five, Standuply, Jell | 대화 요약 또는 HR 평가 | 북스타로 쓰지 않음 |

### 3.2 제품별

#### Dailybot (가장 가까움)

- 루프: 채팅 체크인 → 팀 리포트(미응답자 + 블로커 + AI 요약) → 금요일에 월~금 스탠드업을 주간 요약으로 묶음.
- 공개 카피: `Participants who did not respond yet`, `STANDUP NEVER SUBMITTED`, `Smart Report`의 Highlights / Blockers / Lowlights.
- 주간 섹션: Key wins / Blockers & challenges / Priorities for next week. 메타 예: 5 Days / 35 Reports / 7 Contributors / 3 Blockers.
- 가져올 것: 미제출 명단을 위에, 반복 블로커, 금요일 병합, 요일별 제출+블로커 수.
- 가져오지 말 것: 에이전트/CLI/칭찬 리더보드, 슬랙 봇이 유일한 입력인 전제.

근거: [Dailybot 홈](https://www.dailybot.com/), [Weekly reports](https://www.dailybot.com/solutions/weekly-reports/).

#### Geekbot

- 루프: 슬랙/팀즈 DM으로 질문 → 채널에 브로드캐스트.
- 기본 질문: What have you done since {last_report_date}? / What will you do today? / Anything blocking your progress?
- 우리 스키마와 대응: 완료 / (진행+다음이 한 칸) / 이슈. **요청 칸은 없음.** 기분 질문은 노이즈.
- 가져올 것: 질문 제목이 붙은 보고 카드.
- 가져오지 말 것: 워터쿨러, 투표, 팀 허브 마케팅.

근거: [Geekbot Standups](https://geekbot.com/standups/), [Daily Standup 템플릿](https://geekbot.com/templates/daily-standup).

#### Weekdone PPP

- 주간 상태보고 프레임: Progress(한 일) / Plans(다음) / Problems(이슈).
- 규칙: 막히면 Plans → Problems, 끝나면 Problems → Progress.
- 가져올 것: 주간 3칸, 이슈 생명주기. 프로젝트 흐름의 “미해결/해결”과 맞는다.
- 가져오지 말 것: OKR 나무, 펄스/칭찬.

근거: [PPP 가이드](https://weekdone.com/resources/plans-progress-problems).

#### 플로우 (한국어로 제일 비슷해 보이지만 입력이 다름)

- `게시글 AI → 일일 업무 일지 작성`. 출력 섹션: 오늘 완료한 업무 / 참석했던 일정 / 내일 진행해야 하는 업무.
- 입력은 **플로우 안에 이미 있는 업무·댓글·파일·일정**이지, 메신저/줄글/PPT 붙여넣기가 아니다.
- 주간은 일일 병합이 아니라 `주간 업무 보고서` 양식 템플릿, 또는 OKR 주간 리포트(우선순위 업무, 핵심 결과, 건전성).
- 가져올 것: 버튼 카피, 날짜 선택 후 생성, 완료/내일 섹션 제목.
- 가져오지 말 것: Work OS 전체, 프로젝트 피드, OKR, MateX 숫자 보고서.

근거: [플로우 도움말](https://support.flow.team/ko/flow/29313411403545), [보고·회의 체계화](https://flow.team/ko/wiki/report), [OKR 주간 리포트](https://support.flow.team/ko/flow/17725124738201).

#### 제외한 것들

- **잔디 / 슬랙 / 팀즈**: 대화 요약·검색. 사람×날짜 일일보고 앱이 아님.
- **Lattice / 15Five**: 주간 체크인이 있어도 인사평가·OKR 제품.
- **Standuply / Jell**: 스탠드업 봇. Jell은 2023 인수 이후 북스타로 부적합.
- **한글 / 워드 / 노션**: 문서 도구. 취합·추출 제품이 아님.

### 3.3 화면별 벤치마크

우리 앱 화면 기준으로 쪼갠다.

| 우리 화면 | 벤치마크 | 가져오지 말 것 |
| --- | --- | --- |
| `/report` 보고서 작성 | Geekbot 3질문, 플로우 `AI로 일일 업무 일지` 카피 | 슬랙 봇 UX, 기분/아이스브레이커 |

## 4. 직장인 커뮤니티 실사용 사례

공개 커뮤니티 원글·댓글. 여론은 “일일은 감시, 주간이 정상, 가치는 이슈·성과 취합뿐”으로 모인다.

### 4.1 디시인사이드 중소기업 갤러리

- [일일업무보고 쓰는 회사있냐?](https://gall.dcinside.com/board/view/?id=jungsopd&no=1534029) (조회 544, 댓글 6, 2025-12-01)
  - 본문: 매일 퇴근 전 상세 일일보고. 이직했는데 이것 때문에 퇴사 고민.
  - 댓글: 보통 주간만. 현장은 `업체명 / 장비 / 내용 / 유무상 / 금액`. R&D는 변수·결과분석까지 넣어서 야근. 생산직 부서는 안 써도 되는 곳도 있음. “좆소 좆견이 그런 거 씀”.
- [일일보고서랑 주간보고서](https://gall.dcinside.com/board/view/?id=jungsopd&no=93090)
  - 30분 단위(09:00~20:30)로 빼곡히 적고, 금요일에 일일+주간을 또 씀. 미팅+보고만 하루 1.5~2시간.
- 검색 히트: 일일보고를 상세/요약 **두 개** 쓰는 회사, 근무일지 갑자기 시키기.

### 4.2 클리앙

- [여러분 회사에서 일일업무일지를 쓰시나요?](https://www.clien.net/service/board/park/15147031) (댓글 31)
  - 다수: 안 씀. 주간만. 재택 때만 일일. “노답의 기운”, “없는 말 지어내느라 죽겠더군요”.
  - 일본계 그룹웨어: 보고 라인 + 상급자 댓글 → 정치적.
  - 시간 단위: “업무 시작/종료, 화장실 다녀오겠습니다”까지. 특정인만 시켜서 괴롭힘.
- [갑자기 업무일지 쓰라네요](https://www.clien.net/service/board/park/15924400) (댓글 40)
  - 오전/오후로 나눠 쓰기. 몇 달 하다 사라지는 경우 많음.
  - 실무 양식 증언: **전일 계획 대비 실행 / 금일 업무 / 내일 계획**. 금요일이 월말이면 일+주+월에 한나절.
  - 엑셀 작성 후 메일 복붙. “내용 안 바꿔도 모름”, “줄 수만 봄”.
  - 해외에서는 마이크로매니지먼트·갑질로 분류한다는 댓글.

### 4.3 블라인드

- [일일업무보고 하는 이유가 납득 됨?](https://www.teamblind.com/kr/post/%EC%9D%BC%EC%9D%BC%EC%97%85%EB%AC%B4%EB%B3%B4%EA%B3%A0-%ED%95%98%EB%8A%94-%EC%9D%B4%EC%9C%A0%EA%B0%80-%EB%82%A9%EB%93%9D-%EB%90%A8-tymkguds) (조회 103, 댓글 14, 2025-07-10)
  - 스타트업 아침 1분 구두: “어제 완료했고 오늘은 진행할 예정”. 업무가 서로 다른데 친목·으쌰으쌰가 이유.
  - 댓글: 스크럼을 주워 와서 일일보고로 하는 케이스. 매일 30분~1시간 하면 인생이 아까움.

### 4.4 더쿠 직장인

- [일일 업무보고 쓰는 회사 많아??](https://theqoo.net/job/4202738166) (2026-05-14, 댓글 7)
  - 본문: 예전 회사는 눈에 안 차는 직원만 일간, 이직하니 전원이 매일 (좆소).
  - 댓글:
    - 없다가도 상사 때문에 생김.
    - 대기업: **1시간 단위**, 전직원 공개, 잡도리는 없고 나중에 성과취합에 도움.
    - 관리부서 루틴 업무인데 매일 쓰면 스트레스.
    - 매일 + 주간 둘 다 쓰는 곳.
    - 할 일 없을 때 그거 쓰는 것 자체가 스트레스. 다만 남 업무 파악·성과취합에는 도움.

### 4.5 커뮤니티에서 반복되는 패턴

1. 일일 = 감시/페이퍼워크, 주간 = 그나마 정상.
2. 시간 단위(30분/1시간)는 가장 욕을 먹음.
3. 매니저는 안 읽거나 줄 수만 본다. 그래서 어제 내용 복붙이 성행.
4. 남는 가치는 **이슈 가시성, 미제출, 나중에 성과 취합**.
5. 이중 작성(일일+주간, 상세+요약, 엑셀+메일)이 실제 고통.
6. IT는 구두 스크럼 3문장, 현장은 한 줄(업체/금액), 사무는 칸 몇 개.

## 5. 일일보고 템플릿 유형

예스폼·한글 서식은 제출 파일용이다. 커뮤니티에서 사람이 실제로 복붙하는 것은 짧은 칸이다.

### 5.1 유형 표

| 타입 | 칸 | 출처 | 우리 JSON 매핑 |
| --- | --- | --- | --- |
| 스크럼 3문장 | 어제 / 오늘 / 블로커 | 블라인드, Geekbot | 완료 / 진행+다음 / 이슈 |
| 한국 4칸 | 성과·진행 / 이슈 / 명일 / 특이 | 실무 가이드 | 완료+진행 / 이슈 / 다음 / 요청·특이 |
| 전일대비 | 어제 계획 대비 실행 / 금일 / 내일 | 클리앙 | 완료 / 진행 / 다음 |
| 개조식 불릿 | `-` 나열 | 한국 보고서 기본 | 전 필드 불릿 |
| 시간표 | 09:00~09:30 … | 디시, 더쿠 | 진행 타임라인. 기본값으로 쓰면 안 됨 |
| 오전/오후 | 오전 무엇, 오후 무엇 | 클리앙 | 진행 |
| 현장 한줄 | 업체 / 장비 / 유무상 / 금액 | 디시 | 완료 |
| 표 | 업무명 / 완성률 / 예정 | 예스폼 간단형 | 완료+진행 |
| 건의칸 | 지시 / 애로 / 건의 | 예스폼 | **요청** (커뮤니티 양식에 잘 없음) |
| 부서일지 | 금일 추진 / 계속 추진 | 예스폼 | 완료 / 진행 |
| PPP 주간 | Plans / Progress / Problems | Weekdone | 다음 / 완료 / 이슈 |
| 노션 3줄 | 오늘 한 일 / 막힌 일 / 내일 1순위 | 노션 가이드 | 완료 / 이슈 / 다음 |

실무 4칸 구성 예: 1) 업무 성과/진행사항 2) 이슈 및 해결 방안 3) 명일 업무 계획 4) 특이사항.  
예스폼 상세형: 금일 실시(소요시간, 달성률) / 익일 계획 / 미처리 / 특이.  
노션 가이드: 퇴근 전 5분, 3줄 + 이슈 1줄 + 내일 2줄이 유지된다.

### 5.2 우리 앱에 넣을 붙여넣기 템플릿 (초안)

작성 화면 샘플/칩용. 예쁜 hwp가 아니라 추출기가 받을 원문 형태.

**A. 기본 (가장 많이 씀)**

```
[완료]
-
[진행]
-
[이슈]
-
[내일]
-
```

**B. 스크럼 (IT/스타트업)**

```
어제:
오늘:
막힌 것:
```

**C. 한국 회사 4칸**

```
1. 성과/진행
2. 이슈 (원인 → 영향 → 조치)
3. 내일 계획 (마감 시각)
4. 특이/외근/휴가
```

**D. 전일대비 (클리앙 실무)**

```
전일 계획 대비 실행:
금일:
내일:
```

**E. 요청 칸 (우리 스키마에만 있는 필드)**

```
지시/확인 부탁:
건의:
```

커뮤니티 양식에는 요청이 잘 없어서, 추출기가 이걸 이슈로 빨아들이기 쉽다. 템플릿을 따로 둬야 한다.

**F. 추출 스트레스 테스트**

- 30분/1시간 타임테이블
- 엑셀 표 복붙
- 메신저 대화
- “오늘도 동일” 복붙
- 한 줄: `업체 A / 장비 B / 유상 12만`
- 줄글 일기체
- 업무보고 작성 시간을 업무로 적은 문장

주간 템플릿은 PPP 한 장: `이번 주 한 일 / 막힌 일 / 다음 주`.

## 6. 우리 제품에 대한 시사점

1. **주간 병합이 본게임이다.** 커뮤니티는 일일을 감시로 보고, 주간·이슈·성과 취합만 가치로 인정한다.
2. **기본 템플릿은 4칸 이하.** 긴 한글 양식은 안 쓴다.
3. **시간 단위 양식은 넣되 기본값으로 하지 않는다.** 커뮤니티에서 가장 욕먹음.
4. 셀링 포인트는 “예쁘게 써 주기”가 아니라 **이슈 / 미제출 / 중복 복붙을 튀게 하는 것.** “내용 안 바꿔도 모름”이 현실이다.
5. **현장(업체·금액), 개발 스크럼, 사무 4칸을 처음부터 나눈다.** 한 양식으로 가면 추출이 망한다.
6. **요청은 우리만의 칸이다.** 벤치마크 제품은 블로커와 요청을 구분하지 않는다. 추출·UI에서 이슈와 분리해야 한다.
7. 화면 벤치마크 우선순위: Dailybot(`/`, `/weekly`, `/activities`) → Geekbot(`/report` 필드) → Weekdone(`/project-timeline`, 주간 칸) → 플로우(한국어 카피만).

구현은 이 문서만으로 착수하지 않는다. 화면 변경은 별도 `ㄱㄱ` 또는 미리보기 지시가 있을 때.
